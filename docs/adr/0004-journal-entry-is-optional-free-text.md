# ジャーナル記入は任意の自由記述とし、構造化も必須化もしない

ジャーナルはプロダクトの価値の中核だが、目的は現在の運用（1分の間に Thino で一言メモを残す）を変えずに1つのアプリにすることにある。そのため入力欄は自由記述の1つの欄とし、書かなくても次のフェーズへ進む。「やったこと / 次にやること」の2つの欄に分ければ将来の decision model の精度は上がるが、それよりも書く自由度を優先した。

一方で、ジャーナル記入はセッション中にしか書けない。nanaichi はセッション中のジャーナリングを管理し、自発的に振り返れる場であり、セッションの外で書きたいメモは別のメモ帳に書けば良い。

## Considered Options

- 「やったこと」「次にやること」の2つの欄: decision model には有利だが、感想などが書きにくくなるため不採用
- 書き終えるまで次のフェーズに進まない: 「矯正」は強まるが、今の運用から離れるため不採用
- セッションの外でも書ける（Thino と同じ感覚）: 汎用のメモ帳になり、プロダクトの焦点がぼやけるため不採用
