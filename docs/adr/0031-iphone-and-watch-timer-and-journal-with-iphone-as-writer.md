# iPhone と Watch はタイマーとジャーナルに絞り、記録を書くのは iPhone だけにする

ADR 0015 で Apple の端末は Swift・SwiftUI で作ると決め、ADR 0028 で Mac から作ることにした。その次に作る iPhone と Apple Watch の作り方をここで決める（Issue #69）。ログインと、この端末の記録先は Mac と同じにする（ADR 0028・0029）。

## 範囲はタイマーとジャーナル

- iPhone と Watch で作るのは、タイマーとジャーナル記入だけにする。持ち歩く端末でほしいのは、セッションを回すことと、ジャーナルの1分で一言を残すこと。スタッツ・タスク・タグの管理・設定の画面は、Web と Mac で使う。
- Watch でできるのは、開始・一時停止・再開・中断・終了と、音声入力でのジャーナル記入にする。集中の再開始・進める・休憩スキップは iPhone で行う。Watch の画面にはフェーズと残り時間と何セット目かを出し、フェーズの切り替わりを振動で知らせる。
- Watch の画面は、いちばん小さい Apple Watch SE 3（40mm）にスクロールせずに収める。操作のボタンは文言を出さずにアイコンだけにし（開始・再開は ▶、一時停止は ⏸、中断は ×、終了は電源の記号）、VoiceOver では GLOSSARY の用語を読む。iPhone の同じ操作のボタンは、同じアイコンと文言を並べ、アイコンと操作の結びつきを覚えてもらう。■ は中断にも終了にも読めるので使わない。
- 追記（Issue #122）: 初めは Watch でできる操作を開始と中断だけにしていた。2026-11-28 にオーナーが TestFlight の実機の SE 3 で試し、一時停止・再開・終了を足し、画面を SE 3 に収めてアイコンだけのボタンにすると決めた。
- 対応するのは iOS 26・watchOS 26 以降にする。iPhone で文字にするのに使う SpeechAnalyzer が iOS 26 からで、Mac（macOS 26 以降、ADR 0028）とも揃う。

## Watch は WatchConnectivity で iPhone につなぎ、記録を書くのは iPhone だけ

- Watch と iPhone は WatchConnectivity でつなぐ。Watch は操作（開始・一時停止・再開・中断・終了）と録音した音声を iPhone に送り、iPhone はスナップショットを Watch に送る。Watch は受け取ったスナップショットから、ドメインの関数でタイマーの状態を計算して表示する（ADR 0003）。
- 開始と操作の頼みには、Watch が画面に出している記録先の印（操作ならセッションも）を添える。iPhone のいまの記録先やセッションと食い違えば（Watch に届かないあいだに iPhone がログイン・ログアウトした、ほかの端末で次のセッションを始めたなど）、iPhone は断り、Watch は今の様子を頼み直す。Watch は iPhone に届くようになってから今の様子を確かめ終えるまで、操作を受け付けない。答えが返らなかった頼みは、同じ記録を見たまま押し直したら同じ操作イベントの ID で送り直す（ADR 0007）。
- iPhone は、Watch の頼みを通したスナップショットを、Watch に答える前に自分の画面に反映し、通知の予約し直しが終わるまで待つ。Watch の頼みで裏で起こされたアプリは答えたあとすぐ止められることがあり、アカウントの記録先の同期の接続も裏では切れていることがあるので、同期メッセージを待たない（Issue #122）。
- 記録を書くのは iPhone だけにする。Watch は記録先を持たず、iPhone から届いた操作をワークフローに通すのも iPhone の記録先（ログインしていなければ SQLite、していればアカウント）である。記録を書く場所が1つなら、Watch と iPhone の記録のマージを考えなくてよい。
- 初版の Watch は iPhone を経由して動けばよい。iPhone に届かないあいだの Watch は操作を受け付けず、届かないことを画面に出す。Watch が単体で、iPhone もネットもない状態で動くこと（オフラインでの記録のマージ）は、そのあとに作る（ADR 0015）。
- ただし音声入力の録音だけは、iPhone に届かないあいだもできるようにする。録音は Watch に残しておき、iPhone に届くようになったら送って文字にする。録音は記録を書かず、記録を書くのは届いた音声を文字にした iPhone なので、Watch は記録先を持たないままでよい。

## 音声入力は Watch で録音し、iPhone の SpeechAnalyzer で文字にする

1. Watch で録音する。録音するときに、Watch がその録音の ID を UUID で発行する。録音できるのは、Watch が最後に受け取ったスナップショットがセッション中のときだけにする。
2. 録音したファイルを、録音の ID、録音した時刻、そのときのセッションと一緒に WatchConnectivity で iPhone に送る。iPhone に届かないあいだは Watch に残しておき、届くようになったら送る。
3. iPhone の SpeechAnalyzer で、端末の中で文字にする。
4. 文字にした本文を、録音したときのセッションのジャーナル記入として、録音した時刻で iPhone の記録先に書く。届いたときにそのセッションが終わっていても記入にする（下の「録音したときのセッションに記入する」）。記入の ID には録音の ID をそのまま使う。Watch は iPhone に届いたと確かめられるまで同じ録音を送り直すので、記入の ID を文字にするたびに新しく発行すると、1つの録音から記入が2件できてしまう。録音の ID を使えば、同じ ID の記入は1件しか記録しない ADR 0010 の決まりで、送り直した録音も1件の記入になる。
5. 文字にしたら、音声のファイルを iPhone と Watch の両方から消す。Watch のファイルは、iPhone に届いたことを確かめてから消す。

本文と音声は端末の外に出さない（PRODUCT.md の音声入力の方針、#33）。iPhone に届くのを待つあいだは音声を Watch に置き、iPhone に送ったあとも、音声は Watch と iPhone のあいだを WatchConnectivity で行き来するだけで、端末の外には出さない。文字にするのは iPhone の中である。外に出るのは、文字にしたジャーナル記入を、ログインしているときにアカウントの記録先に書くときだけで、これは画面から記入したときと同じ。文字にしたあとは、音声のファイルをどこにも残さない。本文は Sensitive に相当する型で包み、ログやエラーの文字列には出さない（ADR 0028）。

## 録音したときのセッションに記入する

ジャーナル記入はセッションの外では書けない（PRODUCT.md）が、Watch の録音だけは、届いたときにセッションが終わっていても、録音したときのセッションの記入にする。iPhone に届かないあいだに録音したものは、届くまでにセッションが終わることがあり、そのたびに記入できなければ、録音したものが失われる。録音したのはセッション中なので、録音したときのセッションに、録音した時刻で記入するのが、画面からその場で記入したときにいちばん近い。

これは ADR 0010 の「書いた時刻と紐付きはサーバーが受け付けた時刻のタイマーの状態から決める」の例外で、ADR 0010 にも書いてある。

次のことは、まだ決めていない。#74 で決める。

- 録音した時刻が、そのセッションの自動終了で閉じた時刻より後だったときの扱い
- ログアウトしたあとに届いた録音の扱い
- iPhone に届かないあいだに iPhone でセッションが切り替わったとき（終えて次を始めたなど）、録音の記入先を、Watch が添えたセッションで決めるか、iPhone が録音した時刻から決めるか
- 録音した時刻に iPhone でセッションが動いていなかったとき（手動で終えたあとなど）の扱い

## Watch の OS の音声入力は使わない

watchOS の標準の音声入力（テキスト入力の画面の音声入力）は、端末の中で文字にするか、Apple のサーバーに送って文字にするかを、アプリから指定できない。PII であるジャーナルの本文が端末の外に出ないことを保証できないので使わない。iPhone の SpeechAnalyzer は端末の中で文字にするので、こちらを使う。

## Apple Developer Program への登録と配布

- Apple Developer Program には、実機の Watch で振動を確かめるときに登録する。それまでは iPhone と Watch のシミュレーターで作る。無料の署名では Watch の実機に入れても7日ごとに入れ直しになり、拡張ランタイムセッションなども配布の準備が要る（ADR 0028）。
- 配布（TestFlight・App Store）の方法は、この ADR では決めず後回しにする。ADR 0028 は「配布の方法は iPhone を作るときに決める」としていたが、iPhone と Watch を自分で使えるようになってから決める。
- 追記（Issue #109）: 2026-11-24 に Apple Developer Program に登録し、オーナーの端末へは TestFlight の内部テストで入れることにした（ADR 0032）。App Store への公開はまだ決めない。

## 確かめ方

- iPhone は、iOS のシミュレーターの上で e2e（`@e2e-dev/mobile`）と XCUITest で確かめる（ADR 0028）。
- Watch は、watchOS のシミュレーターの上で XCUITest で確かめる。e2e は watchOS に対応していない。画面が収まるかは、いちばん小さい Apple Watch SE 3（40mm）のシミュレーターで確かめる。
- 振動はシミュレーターでは確かめられないので、実機の Watch でオーナーが確かめる。
- ドメインとワークフローは、Mac と同じ Swift Package の `swift test` で確かめる。

## Consequences

- ADR 0028 の「機能は Web にあるものをすべて入れる」は、iPhone と Watch には当てはめない。Mac は Web にあるものをすべて入れ、iPhone と Watch はタイマーとジャーナルに絞る。
- Watch は記録先を持たないので、Watch 単体での動作を作るときは、Watch に記録先を置き、iPhone の記録とマージするしくみを別に決める。
- iPhone に届かないあいだは Watch で操作できない。手首だけで使い続けたい場面には、Watch 単体での動作ができるまで応えられない。
- iPhone に届かないあいだも録音はできるが、ジャーナル記入になるのは iPhone に届いて文字にしたあとになる。それまで録音は Watch に残り、iPhone に届いたことを確かめるまで消せない。
- 「ジャーナル記入はセッション中だけ」に、Watch の録音という例外ができる。記録先は、終わったセッションへの記入を、Watch の録音から来たものに限って受け付ける。
- 音声入力は iPhone がないと文字にできない。Watch 単体での動作を作るときに、Watch の中で文字にする方法を改めて考える。
- 振動の確かめはオーナーの手元の実機に頼り、CI では確かめない。
- Watch の画面は e2e のテストの一覧に入らず、XCUITest の一覧になる。

## Considered Options

- **Watch の OS の音声入力を使う**: 実装は小さく、iPhone がなくても文字にできる。しかし端末の中で文字にすることをアプリから指定できず、本文が外に出ないことを保証できない。
- **Watch も記録先を持ち、iPhone と両方で書く**: iPhone に届かなくても Watch で操作できる。しかし2つの記録先のマージ（同じセッションへの操作の重なり、時刻の前後）を初版から決めることになる。ADR 0015 のとおり、Watch 単体での動作はそのあとに作る。
- **届いたときにセッションが終わっていた録音は記入にせず、消して Watch に知らせる**: 「セッションの外では書けない」に例外を作らずに済む。しかし iPhone に届かないあいだに録音したものほど失われやすく、届かないあいだも録音できるようにした意味が薄れる。
- **Watch が直接サーバーにつなぐ**: iPhone がなくてもネットがあれば動く。しかしログインしていない人の記録は iPhone の端末の中にあるので、Watch から書けない。Watch にもトークンを置くことになり、ログインの流れも Watch 用に要る。
- **iPhone も Web にあるものをすべて入れる（ADR 0028 の Mac と同じ）**: スタッツやタスクの画面は、持ち歩く端末で使う場面が少なく、先にタイマーとジャーナルの体験を固めたい。
