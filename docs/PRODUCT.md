# nanaichi — プロダクト仕様

> 用語の定義は [`GLOSSARY.md`](../GLOSSARY.md)、覆しにくい判断の理由は [`docs/adr/`](./adr/) を参照。

## コンセプト

7分の集中 + 1分のジャーナルを1セットとし、これを繰り返すことで flow 状態を維持する。
ポモドーロテクニックの派生だが、以下が決定的に違う。

- **1セット = 集中7分 + ジャーナル1分 = 8分**。3セットごとに休憩5分。
- ジャーナルは「そのセットの振り返り」と「次にやることの整理」を促すための仕組み。ここがプロダクトの価値の中核。ただし書くかどうかは任意（ADR 0004）。
- 25分ですら長いと感じる人のために、短いサイクルを守らせる。

### 原体験（現在の運用）

手元のポモドーロタイマーを7分+1分にセットし、1分の間に Obsidian（Thino）で一言メモを残している。
**運用方法はこれとほぼ変えず、タイマーとメモが1つのアプリになっていること**が大事。

## 開発方針

- 最終ゴールは iPhone + Apple Watch のネイティブアプリだが、最初からネイティブは厳しい。
- まず**将来ネイティブが使うバックエンド API + Web 画面**を作り、自分でドッグフーディングする。
- ネイティブは Apple の端末（iPhone・Apple Watch・Mac）だけを Swift・SwiftUI で作る。Windows・Linux・Android は当面 PWA で受ける（ADR 0015）。

## MVP の仕様

### タイマー

- 時間とセット数は固定（集中7分 / ジャーナル1分 / 休憩5分 / 3セットで1ラウンド）
- カウントダウンを表示する
- セッションの開始のみ手動。以降のフェーズは全て自動で進む（現在使っているポモドーロタイマーと同じ）
- 休憩はスキップでき、すぐ次の集中を始められる
- 一時停止はどのフェーズでもできる。一時停止した時間は記録に残す
- 中断は集中中のみ。中断すると待機に戻り、次の集中は手動で同じセット番号からやり直す
- セッションの終了は手動。ただし止め忘れの保険として、ジャーナル記入も操作もないまま2ラウンドが過ぎたら自動終了する（最後の記入・操作の時刻で閉じ、それ以降のセットは記録しない）
- フェーズの切り替わりは音とブラウザ通知で知らせる（Web Push は作らない）
  - 音を鳴らすか・音量（小・中・大）・切り替わった先のフェーズごとの音色（鐘・木琴・電子音・やわらか）・ブラウザ通知を出すかは、端末ごとに選べる（知らせ方の設定）。音は試しに鳴らして確かめられる。音色の既定は、どのフェーズも鐘
  - 音は Web Audio で合成し、音源のファイルは持たない
- セッション中は画面の自動消灯を防ぐ

### ジャーナル記入

- 入力欄は自由記述の1つの欄。プレーンテキスト（改行可）。表示時に URL のみ自動でリンクにする
- セッション中ならいつでも何件でも書ける（送信すると入力欄が空になり、続けて書ける）。セッションの外では書けない
- 編集・削除できる
- タグをつけられる（Issue #31、ADR 0013）
  - 入力欄の上のタグの欄で、複数つけられる。入力中は使ったことのあるタグを、最近使った順に候補に出す。候補にないものはその場で新しく作れる
  - つけたタグは送信しても外れず、外すかセッションが終わるまで続けて書く記入につく。端末ごとに覚える
  - タグはセッションの外でもつけられる（記入はセッション中だけ）。開始前に「これをやる」と準備したタグは、始めたセッションに持ち越す
  - 本文は必須のまま（タグだけの記入は書けない）
  - 書いた記入のタグは、編集でつけ直せる
  - 使えるタグは20種類まで（どの記入にもついていないタグは数えない）
  - タグごとの完了セットはスタッツに出す（Issue #35）。タグで記入を絞り込む一覧は、まだ作らない
- タイムラインは1本で、スクロールで過去にさかのぼれる。別の履歴画面は作らない
  - 日付とセッションの区切りを挟む。日付の区切りにその日の完了セット数と集中時間を、セッションの区切りにそのセッションのその日の完了セット数と集中時間を表示する
  - 日付は端末のタイムゾーンの 0:00 で区切る

### 画面

タイマーの1画面と、その上に重ねる設定画面・スタッツ（PC・スマホ共通）。

- 上部: カウントダウン、現在のフェーズ、何ラウンド目・何セット目か、開始・一時停止・中断・終了のボタン
  - 一時停止中は、止めてからの時間を出す
  - 集中時間（完了セットの集中だけを数える）を、今日の分はヘッダーに、セッション中はそのセッションの分をタイマーの下に出す（Issue #34）
  - セッションが終わったら、セッションのまとめ（始めた・終わった時刻、集中時間、完了セット、ジャーナル記入の数、不成立セットを含むセットの並び）を出す
- 中央: 入力欄。送信キーは「Enter で改行、⌘+Enter（Mac 以外は Ctrl+Enter）で送信」（既定）と「Enter で送信、Shift+Enter で改行」から選べ、送信ボタンの隣で切り替える。端末ごとに覚える。ジャーナルのフェーズに入ったら自動でカーソルを置く
- 下部: タイムライン（新しい記入が上）
- 設定画面: ヘッダーの設定のボタンから開く（Issue #34）。知らせ方の設定、表示（テーマ: 端末に合わせる・ライト・ダーク）、記入（送信キー）、アカウント（ログアウト）。端末ごとの設定には「この端末」と示す
  - タイマーの画面の上に重ねて開くので、開いている間もタイマーは進み、フェーズの切り替わりも知らせる。ヘッダーに裏で進んでいるタイマーを出す
  - テーマは端末ごとに覚え、開き直したときもちらつかずにその明るさで出す
- スタッツ: ヘッダーのスタッツのボタンから開く（Issue #35）。設定画面と同じく、タイマーの画面の上に重ねて開き、タイマーと知らせは進み続ける
  - 期間: 今日・週（月曜始まり）・月・すべて。日付と時間帯は端末のタイムゾーンで区切る
  - 期間ごと: 集中時間（前の期間の同じ時点までとの差）・完了率（不成立セットの数）・ジャーナル記入の数と記入率・日ごとの集中（週と月は日ごと、すべては月ごと。今日は出さない）・タグごとの完了セット（多い順に5つ）・時間帯ごとの集中といちばん多い時間帯
  - 期間に関わらず: 連続日数（と最長）、この12週間の日ごとの集中
  - その期間に記録がなければ、そう伝えて、始め方を案内する
  - 数えるのはサーバー（ADR 0014）。ヘッダーの今日の集中時間も同じ数え方で、1日にセッションが多くてタイムラインを読み込みきれない日も数えられる

### 同期・アカウント

- Google ログイン
- 実行中のタイマー状態とジャーナル記入は、複数タブ・複数デバイスでリアルタイムに同期する
- ドッグフーディング中は、許可したメールアドレスのみ登録できる
- PWA としてホーム画面に追加できる

### 作らないもの

- 時間・セット数・自動遷移のカスタム設定
- Obsidian 連携・書き出し（将来 MCP 経由、ADR 0005）
- スタッツの書き出し・共有、目標（1日に何セットなど）の設定
- Web Push
- Web での音声入力（Web Speech API）。Chrome は音声を Google のサーバーに送って文字にするため、PII であるジャーナルの本文が外に出る。また Chrome 以外の Chromium 系では API があっても動かないことがあり、使えるかを判定できない。macOS・iOS の OS の音声入力は今の入力欄でも使える。音声入力は端末の中で文字にできるネイティブアプリでだけ扱う（#33）

## MVP の完了条件

Obsidian と手元のポモドーロタイマーをやめて、**nanaichi だけで1週間過ごせたら**ドッグフーディング開始とする。
そこで出た不満点をもとに次に作るものを決める。

## 技術構成

- 単一の Cloudflare Worker に Hono API + Vite React SPA を同居（ADR 0001）
- 認証: Better Auth + Google ログイン
- データ: D1（認証・将来の課金）+ ユーザーごとの Durable Object（タイマー状態・セッション・ジャーナル記入）（ADR 0002）
- タイマー状態は時刻とイベントから計算する（ADR 0003）
- Vite+（`vp`）の pnpm monorepo。lint は Oxlint、フォーマットは Oxfmt。最初は `apps/web` のみ（ADR 0006）
- UI は Tailwind CSS v4 + shadcn/ui（土台は Base UI。`components.json` の style は `base-vega`）
- ドッグフーディング中の URL は `*.workers.dev`
- 本番環境のみ。main への push で GitHub Actions から `wrangler deploy`

## 長期ゴール（スコープ外だが設計上想定しておく）

- **iPhone + Apple Watch ネイティブアプリ**（Bluebird のような出来の良いタイマー体験を踏襲）。Swift・SwiftUI で作り、そのあと Mac（メニューバー常駐）も同じ Swift Package の上に作る（ADR 0015）
  - ドメインは TS と Swift の2つで持ち、TS のテストケースを書き出したゴールデンケースを両方で通して、同じ振る舞いをすることを確かめる
  - デザインは OS 間で揃えず、それぞれのプラットフォームの流儀に合わせる
  - Watch の振動、フェーズの切り替わりのローカル通知、Live Activity などネイティブでしか得られない知らせ方を使う
  - Watch からの操作では音声入力でジャーナル記入できることが望ましい（Apple の端末の中で文字にする音声認識を使う。Web では作らない、#33）
  - 初版の Watch は iPhone 経由の同期で動けばよい。その後、Watch が単体でオフラインでも動くようにする（ADR 0003）
  - App Store 審査上、Google ログインを出すなら Sign in with Apple 等の併設が必要になる見込み。ネイティブは Bearer トークン認証
- **月額課金**（自分で使って良いと思えることが前提なので当面は考えない）
  - Web は Stripe、iOS は IAP の二系統になる見込み（ADR 0002）
- **カスタム設定**: 集中・ジャーナル・休憩の時間、休憩までのセット数、各遷移を自動で進めるかどうか
- **MCP サーバー**: Obsidian への連携やジャーナルの振り返りを MCP 経由で行う（ADR 0005）
- **Decision model によるタスク管理**: タスク一覧を持ち、ジャーナル記入から「消化したタスク」へのチェックや「追加すべきタスク」の追加を高速・安価に自動判定する
